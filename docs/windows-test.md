# Windows での録画アプリの動作確認手順

開発環境（Linux）では Windows 向けのコンパイルチェック（`cargo clippy --target x86_64-pc-windows-gnu`）までしか確認できていません。
この手順で、実機での録画アプリ（`fdmv-recorder`）の動作を確認してください。

必要なもの: Windows 10 バージョン 2004（ビルド 19041）以降。アプリ単位の音声の録音に必要です。

## 1. 準備とビルド

[MSYS2](https://www.msys2.org/) を入れ、**UCRT64** のシェルで:

```sh
pacman -S mingw-w64-ucrt-x86_64-{rust,dav1d,opus,pkgconf,gcc,ffmpeg}
cd <プロジェクトのフォルダ>
cargo test --workspace
cargo build --release
```

実行するときは、`C:\msys64\ucrt64\bin` に PATH を通しておきます（DLL と ffmpeg のため）。UCRT64 のシェルから起動すれば通っています。

## 2. 自己テスト（自動）

```sh
FDMV_TEST_PATTERN=1 FDMV_DEBUG_SCREENSHOT=rec.ppm ./target/release/fdmv-recorder
```

- 何かアプリのウィンドウが開いている状態で実行してください。
- テストパターンを 4 秒録画して保存し、自動で閉じます。端末に `debug: saved …` と出れば成功です。

## 3. 手動で確認すること

ブラウザで音の出る動画を、別のアプリ（メディアプレーヤーなど）で音楽を再生しておき、`./target/release/fdmv-recorder` を起動します。

| # | 確認内容 | 期待する結果 |
|---|---|---|
| 1 | 左上の「映像」の一覧 | 「画面全体」「モニター 1…」と、開いているウィンドウが並ぶ |
| 2 | モニターを選ぶ | プレビューが出る。表示スケール 125% などでも、モニター全体がずれずに映る |
| 3 | 右の「音声」の一覧 | ウィンドウを持つアプリ（プロセス）が並ぶ |
| 4 | ブラウザに ✓・メイン、プレーヤーに ✓、「マイクも録音する」に ✓ | 録画開始ボタンが押せる |
| 5 | 録画開始 → 20 秒ほど待つ | ブラウザ・プレーヤー・マイクのレベルメーターが別々に動く |
| 6 | 停止して保存 | 「保存しました」と出る。「再生」でプレイヤーが開く |
| 7 | プレイヤーで再生 | 既定ではブラウザの音だけが鳴る。チェーンの ✓ でほかの音を重ねられる。映像と音がずれない |
| 8 | 映像に「ウィンドウ: …」を選んで録画 | そのウィンドウだけが録画される |
| 9 | `./target/release/fdmv verify "<保存したファイル>"` | "result: OK" |
| 10 | 下の「エンコーダ」欄 | GPU があれば「自動: GPU（NVIDIA / Intel / AMD …）」になる。ゲームを録画しても重くならない |

## 4. 既知の制限

- ウィンドウの録画は ffmpeg の gdigrab でウィンドウのタイトルを指定して行うため、録画開始後にタイトルが変わっても続きますが、開始時点のタイトルと一致するウィンドウが無いと失敗します。
- アプリの音声は、選んだプロセスとその子プロセスの音です（ブラウザのタブごとには分けられません）。

## 5. 報告してほしい情報

- Windows のバージョン: `winver` の画面、または `cmd /c ver`
- 手順 1〜3 の結果（うまくいかなかった項目は端末の出力も）
